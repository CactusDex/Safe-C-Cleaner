# Test checklist — Safe C: Cleaner 0.2.1

## 1. Build / startup

1. Распаковать проект в новую папку.
2. Запустить `BUILD-WINDOWS.cmd`.
3. Дождаться `Verified app resource PRI` и `READY`.
4. Запустить `artifacts\SafeCCleaner-win-x64-portable\SafeCCleaner.exe`.

Ожидается: окно открывается без XAML ошибки, версия на вкладке «Безопасность» — 0.2.1.

## 2. SAFE scan

Нажать «Сканировать».

Ожидается:
- User Temp / Windows Temp показывают только временные файлы старше 7 дней;
- системные BSOD-дампы находятся в Quick Clean как ADVANCED и не отмечены автоматически;
- SAFE reclaimable не включает ADVANCED категории.

## 3. SAFE cleanup report

Нажать «Очистить безопасное».

Ожидается:
- очистка выполняется;
- при Windows Temp / system WER появляется UAC;
- на главной карточка «Последняя операция» показывает свободное место до → после;
- свежие temp-файлы не удаляются.

## 4. System crash dumps

Если в системе есть `%SystemRoot%\MEMORY.DMP` или `%SystemRoot%\Minidump`:

1. Открыть «Быстрая очистка».
2. Найти «Системные дампы Windows».
3. Нажать «Очистить».

Ожидается:
- появляется предупреждение о потере данных для анализа BSOD;
- после подтверждения появляется UAC;
- удаляются только известные `MEMORY.DMP` / Minidump, произвольный путь передать нельзя.

Если дампов нет — категория должна показывать 0 B.

## 5. DISM analysis

Открыть «Глубокая очистка» → «Старые компоненты Windows» → «Анализировать».

Ожидается после UAC:
- понятный итог: рекомендует Windows очистку или нет;
- структурированная сводка: фактический размер, резервные компоненты, reclaimable packages, дата последней очистки (если DISM вернул эти поля);
- кнопка «Очистить» активируется только когда Windows рекомендует cleanup.

## 6. Diagnostics

Если приложение не запускается или падает:

`RUN-DIAGNOSTIC.cmd`

Лог:

`%LOCALAPPDATA%\SafeCCleaner\startup.log`
